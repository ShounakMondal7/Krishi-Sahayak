1. Executive Summary

1.1 Problem Statement

Indian agriculture sustains over 140 million farming households, representing the backbone of national food security. Approximately 86% are smallholder and marginal farmers operating on less than 2 hectares. Despite advancements in agronomic research, smallholder farmers face severe structural challenges:

  • Linguistic Exclusion & Illiteracy: India has 22 official languages and hundreds of regional dialects. Most agricultural portals and mobile apps are authored in formal English or standardized Hindi, leaving regional language speakers and illiterate farmers unable to access verified guidance.
  • Pesticide Overuse & Pest Misdiagnosis: Due to lack of real-time diagnostic support, farmers often consult commercial pesticide retailers, leading to chemical misapplication, hazardous over-spraying, environmental degradation, and debt cycles.
  • Severe Public Extension Deficit: The ratio of Krishi Vigyan Kendra (KVK) extension officers to operational farmers is constrained (~1:1,200), causing critical advice delays during acute pest outbreaks or climate shocks.
  • LLM Hallucination Liabilities: General-purpose AI models frequently hallucinate chemical dosages or invent plant treatments, posing direct threats to crop survival and farmer livelihoods.

1.2 Target User Base

  • Primary: Smallholder and marginal farmers across all 28 Indian States and 8 Union Territories, spanning diverse literacy levels and regional languages.
  • Secondary: Village Panchayat operators, Primary Agricultural Credit Society (PACS) workers, and KVK field extension staff assisting farmers in rural centers.

1.3 Core Value Proposition

Krishi Sahayak (कृषि सहायक) bridges this scientific extension gap with a tri-modal, 22-language native localized, RAG-grounded advisory platform:

🌱 Strictly Grounded RAG Intelligence

100% of advisory responses are retrieved from verified ICAR and State Agricultural University manuals via ChromaDB. Zero reliance on generative LLM training data.

📸 Two-Stage Visual Crop Diagnostics

GPT-4o Vision is strictly constrained to objectively describe visible plant symptoms. Those descriptions are then matched against ICAR manuals to formulate treatment protocols.

🗣️ Voice-First Oral Interface

Complete support for regional spoken input (Google Cloud STT / Whisper) and natural speech output (WaveNet / Neural2 TTS) enables illiterate farmers to receive spoken advice.

🌐 22 Official Languages in Native Script

Full offline client dictionaries and deep neural translation (IndicTrans2) cover all Eighth Schedule languages in their authentic scripts (Devanagari, Ol Chiki, Meitei, Gurmukhi, etc.).

3. End-to-End Data & Interaction Flow

Krishi Sahayak implements three multimodal ingestion pipelines (Voice, Image, Text) that converge into a unified RAG grounding and translation pipeline:

3.1 Step-by-Step Query Execution Trace

  1. Input Acquisition:
    • Voice: Farmer taps and holds the microphone button. Audio is recorded via expo-av (WEBM_OPUS for web, LINEAR16 for native) and sent as multipart data to POST /api/v1/query/voice.
    • Image: Farmer takes a photo of an infected leaf. expo-image-manipulator downsamples the image to 1024x1024 px JPEG (< 500 KB) and sends it to POST /api/v1/query/image.
    • Text: Farmer types a query in their native script or Latin transliteration and sends it to POST /api/v1/query/text.
  2. Speech Recognition & Vision Pre-Processing:
    • Voice bytes are transcribed into native text using Google Cloud Speech-to-Text with regional language tags (e.g., ml-IN, hi-IN, ta-IN).
    • Image bytes are analyzed by GPT-4o Vision under a strict prompt: "Describe only visible physical symptoms. Do NOT diagnose or suggest treatments." Output: "Yellow halo surrounding dark necrotic lesions with concentric rings on lower leaves."
  3. Pivot Translation to Standard English:
    • Native text queries are translated into English using IndicTrans2 (IIT Madras). Using English as an intermediate semantic pivot prevents cross-lingual vector fragmentation and ensures alignment with official ICAR scientific research papers.
  4. Vector Embedding & ChromaDB Retrieval:
    • The English query is encoded into a 384-dimensional dense vector using paraphrase-multilingual-MiniLM-L12-v2.
    • ChromaDB executes a cosine distance search across 29 curated ICAR knowledge manuals, extracting the top 3 verified text chunks with similarity scores > 0.40.
  5. Grounded Advisory Synthesis (Zero-Hallucination):
    • The retrieved ICAR chunks and the query are passed to GPT-4o-mini with an immutable system prompt: "Answer ONLY from the context provided below. If context is insufficient, return the standardized KVK referral message."
    • The LLM formats a practical response: Identification of cause, recommended organic/biological controls, verified chemical dosages (if necessary), and preventative cultural practices.
  6. Reverse Translation & Native Delivery:
    • IndicTrans2 translates the English advisory back into the farmer's native regional language and native script.
    • The mobile app renders the response inside AdvisoryResponseSheet.tsx with high-contrast text and action badges.
  7. Bandwidth-Efficient On-Demand Speech Synthesis:
    • To preserve cellular data on 2G/3G connections, audio is not generated automatically. When the farmer taps the speaker icon, the app calls GET /api/v1/query/{query_id}/audio.
    • Google Cloud WaveNet / Neural2 TTS synthesizes natural spoken audio (MP3) and streams it directly to the device. Audio bytes are cached in memory via an LRU cache.

5. Localization Strategy: 22 Official Indian Languages

5.1 The Pan-India Linguistic Architecture

India's agricultural heartlands span 28 states with distinct scripts and dialects. Krishi Sahayak implements a dual-layer localization model:

  • Layer 1 (Client-Side Static UI): 23 native-script JSON dictionaries stored locally in frontend/mobile/locales/*.json. Every dictionary contains 184 identical key-value pairs covering crop names, navigation, pest alerts, and weather cards. These render instantly with zero network requests.
  • Layer 2 (Server-Side Dynamic AI): IndicTrans2 (IIT Madras) performs real-time neural translation between regional dialects and English for unstructured agronomic questions and generated answers.

Selected Language Dict (e.g. sat.json) → Base English Dict (en.json) → Raw Key Literal.
This guarantees the mobile app never crashes, encounters null-pointer exceptions, or renders empty UI elements during network loss.

6. Safety, Verification & Zero-Hallucination Guardrails

Agricultural advisories carry real-world financial and ecological consequences. An incorrect chemical recommendation or dosage can cause plant toxicity or severe crop loss. Krishi Sahayak enforces five strict safety guardrails:

1. Immutable Hardcoded System Prompt

Located in backend/app/services/llm.py. The system prompt is hardcoded in Python and isolated from runtime input, preventing prompt injection attacks from adversarial queries.

2. Contextual Lock-In (Retrieval Constraint)

The LLM is explicitly instructed to disregard general pre-training data and answer ONLY using the provided context chunks. It is forbidden from speculating beyond retrieved ICAR manuals.

3. Standardized KVK Referral Fallback

If ChromaDB similarity search returns zero chunks matching the query threshold (> 0.40 cosine score), the engine returns: "I don't have verified information about this in my knowledge base. Please contact your local Krishi Vigyan Kendra."

4. Two-Stage Vision Separation

GPT-4o Vision is strictly restricted to describing physical symptoms (lesions, chlorosis, pests). It never diagnoses diseases or prescribes chemicals directly, eliminating visual misclassification risks.

5. Extractive Non-LLM Fallback

If external LLM APIs experience outages or rate-limiting, an automated extractive parser synthesizes key advisory sentences directly from raw ICAR documents, providing 100% grounded continuity.
